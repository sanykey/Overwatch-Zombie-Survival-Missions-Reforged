# Overwatch Zombie Survival Missions Reforged

A rework of the [Zombie Survival Missions](https://workshop.codes/786TW) mode for the Overwatch Workshop, based on **ZSMM (786TW)**. The original version is preserved in [ZSM examples/ZSMM (786TW)](<ZSM examples/ZSMM (786TW)>).

The project aims to reduce the script's element count as much as possible and remove unnecessary code, making room for new mechanics and hero improvements. The initial focus is on technical optimization; specific gameplay changes will be documented here as the project develops.

## Changes

### Technical Optimization

The current OverPy 9.7.20 build uses **26,628 elements**, freeing up **5,636** compared with the original ZSMM's 32,264. Global variables: **103/128**; player variables: **82/128**.

- Two Laser Barricade collision checks now use a dot product instead of a trigonometric projection onto the saved unit edge direction: **26,662 → 26,628 (−34 elements)**, without new variables. The original absolute value, barricade-width clamp, horizontal point projection, four independent rule conditions and target filter remain. The isolated build changes only `LASER BARRICADE BLOCKS ZOMBIES` and emits no warnings. Numerical checks found differences only at the exact 1.5 m boundary due to floating-point operation order; in-game behavior and runtime load have not been measured.

- Seven frequently used consumable effect and HUD IDs now use dedicated player variables instead of `powerUpEntityIdList`: **26,718 → 26,662 (−56 elements)** for 7 additional player slots. The moved IDs are No Cooldowns HUD, Air Strike Ring, Cloaking Device Sphere, Super Nano Good Aura, Bounce Pad Ring, Ultimate Charger HUD and Stun Beam. All corresponding reads, writes and deletions were replaced; turret IDs with computed indices remain in the array. Replacing the fields with their former indexed expressions restores the original consumable source; only the seven corresponding subroutines changed among 237 compiled rules, with no emitted warnings. In-game validation and runtime benchmarks have not been performed.

- Bounce Pad applies one impulse to the already filtered player list instead of looping over each player: **26,728 → 26,718 (−10 elements)**, without new variables. Direction, strength, motion mode, sound effect and the 0.125 s interval are preserved. Only `bouncePad` changed among 237 compiled rules; the compiler emitted no warnings. Simultaneous activation for multiple players has not yet been tested in-game.

- Satellite terminal repair counts players within the current terminal's radius once per pass in the existing `tmp1`: **26,736 → 26,728 (−8 elements)**, without new variables. The `> 0` and `> 1` checks use that count before any wait; the 0.4 and 1.1 progress increments, progress cap, messages and 0.5 s interval are preserved. The build emitted no warnings. In-game validation and runtime benchmarks have not been performed.

- Ground item type is read once into the existing `tmp0` before range validation and orb/label creation: **26,746 → 26,736 (−10 elements)**, without new variables. The snapshot is refreshed each pass; color and name are read at creation, while only visibility reevaluates. Separate effect/text position indices, original colors/names and created-handle registration are preserved. `node analysis/verify-ground-powerup-id.cjs` compares all 237 compiled rules after substituting the ID expression back and rejects four unsafe variants, including live color/string reevaluation through scratch. In-game validation and runtime benchmarks have not been performed. [Validation results](analysis/ground-powerup-id-validation-2026-11-03.json).

- Objective cleanup reads each ID once per iteration into the existing `tmp0`, then performs the original six deletions before waiting: **26,759 → 26,746 (−13 elements)**, without new variables. The loop index remains in `phaseSlot0` across `wait()`; the ID is read again after each wait. `node analysis/verify-objective-cleanup-id.cjs` compares all 237 compiled rules after substituting the original ID expression back and rejects three unsafe variants. Deletion order, the wait and list reset are preserved; shared HUD validation also passes. In-game validation and runtime benchmarks have not been performed. [Validation results](analysis/objective-cleanup-id-validation-2026-11-03.json).

- Bot teleport target-position averaging now uses one shared loop and one synchronous snapshot of the selected list: **26,774 → 26,759 (−15 elements)**, without new variables. The selection condition, summation order and original loop-counter divisor are preserved; compiled loop factoring was checked and the other 236 rules match. Comments document existing edge cases: an empty list yields a zero center, and targets can disappear during waits before destination selection; guarding these cases requires a separate fix. In-game validation and runtime benchmarks have not been performed.

- Kill Zone and Zombie Egg now share the synchronous `createRemainingObjectivesHud`: **26,780 → 26,774 (−6 elements)**, without new variables. The red/lime-green initial color is passed through `tmp2` immediately before the call and read only at creation; only visibility reevaluates using the original `getAllPlayers()` expression. Text, position, sort order, HUD count and immediate ID registration for cleanup are preserved. `node analysis/verify-remaining-objectives-hud.cjs` compares all 236 original compiled rules after restoring the two calls and rejects four unsafe changes, including color reevaluation and missing ID registration. In-game validation and runtime benchmarks have not been performed. [Validation results](analysis/remaining-objectives-hud-validation-2026-11-03.json).

- Combined two identical `ReconnectStatus.ALIVE` record writes in the synchronous `saveAlivePlayerState`: **26,793 → 26,780 (−13 elements)**, without new variables or `tmp0..2` usage. Both original save points remain after the living player's timer reset and after user registration; the helper saves the same five fields at the same `eventPlayer` index. `DOWNED`/`DEAD` writes are unchanged. `node analysis/verify-alive-player-save.cjs` compares all 235 original compiled rules after substituting the record write for each call and rejects three unsafe variants. Reconnect validation also passes; its baseline now isolates the snapshot optimization from unrelated changes in the same file. In-game validation and runtime benchmarks have not been performed. [Validation results](analysis/alive-player-save-validation-2026-11-03.json).

- Boss Behemoth gas processing reads each cloud's position and updated radius once into the existing `tmp1`/`tmp2`: **26,801 → 26,793 (−8 elements)**, without new variables. Snapshots are assigned after radius growth and consumed only by the synchronous target filter before the wait; visual effects keep reading the original arrays. Radius growth, target deduplication, damage and the 0.25 s tick are preserved. `node analysis/verify-gas-cloud-snapshots.cjs` compares all 235 compiled rules after substituting the snapshot expressions back, audits ordering and scratch lifetimes, and rejects three unsafe variants. In-game validation and runtime benchmarks have not been performed. [Validation results](analysis/gas-cloud-validation-2026-11-03.json).

- The synchronous `checkEnhancementPlacement` shares Laser Barricade and Charge Battery rejection checks after button release: **26,816 → 26,801 (−15 elements)**, without new variables. Its `tmp0` result is immediately consumed by an abort in the calling rule. The 31 m validation ray, 30 m threshold, death check, separate placement rays, effects and cooldowns are preserved. `node analysis/verify-enhancement-placement.cjs` compares all 234 original compiled rules after restoring the two rejection checks, audits synchronous execution and scratch lifetimes, and rejects four unsafe variants. In-game placement validation has not been performed. [Validation results](analysis/enhancement-placement-validation-2026-11-03.json).

- Saved reconnect-row fields are named using `ReconnectField`, and player states using `ReconnectStatus`. Snapshot and live-row reads, status comparisons and row writes use the enums. All 234 compiled rules match the numeric version; element and variable counts are unchanged.

- Six reconnect-state row reads now use one snapshot in the existing `tmp0`: **26,834 → 26,816 (−18 elements)**, without new variables. The snapshot is used only in the synchronous segment before `kill()` and the wait; the later status check still reads the current `playerStatsList`. `node analysis/verify-reconnect-row.cjs` compares all 234 compiled rules after substituting the snapshot expression back, checks scratch lifetimes and rejects an inserted wait or asynchronous launch before snapshot consumption. In-game reconnect validation has not been performed. [Validation results](analysis/reconnect-row-validation-2026-11-03.json).

- Extracted the Zombie Mode and Objective Type winner selection into the synchronous `selectVoteWinner`: **26,866 → 26,834 (−32 elements)**, without new variables. Its `tmp0..2` inputs and result are consumed before waits or asynchronous launches; the helper contains no waits, asynchronous actions or nested calls. The original loops, random tie-breaking conditions and separate no-preference defaults are preserved. `node analysis/verify-vote-winner.cjs` compares all 233 original compiled rules after substituting the helper body, checks scratch lifetimes and rejects four deliberately unsafe changes. In-game validation has not been performed. [Validation results](analysis/vote-winner-validation-2026-11-03.json).

- Replaced two zombie-type cap conditional expressions with `max()` and removed 14 redundant `abs()` wrappers around nonnegative `angleBetweenVectors()` results: **26,896 → 26,866 (−30 elements)**, without new variables. All 233 compiled rules match after normalizing only these expressions; the build through includes was also verified. Gameplay thresholds are preserved; in-game validation has not been performed. - Fixed the import error `Player variable '15' is too long`: the physical name `enhancementHitchhikerCarrierPoolId` (34 characters) was shortened to `enhancementCarrierPoolId`, with the old name retained as an alias. Build validation now checks the length of exported global variable, player variable, and subroutine names and reproduces the rejection of the old name. - Effect, HUD, and power-up modifier ID indices are now named using `PowerUpEntitySlot`: 26 values replace numeric indices in `powerUpEntityIdList`. The starting index for the turret legs and the turret cleanup bounds also use the enum. The original index values, variable count, and element budget are preserved.

- The three menu votes and item exchange data were moved from arrays to individual fields; sharing slots across phases required only one additional `playervar`. The difficulty vote shares a slot with the exchange position, the objective vote with the exchange index, and the zombie mode vote with the previous item's ID. Guards against late menu writes are preserved; all exchange data is assigned before it is read and survives waits in separate slots. Spawn point removal was extracted into a shared subroutine; nine zombie control resets were consolidated into two subroutines while preserving action order. A shared constant power-up palette replaces two color copies and a temporary HUD copy. Results for this stage: **27,102 → 26,902 (−200 elements)**, **102 → 103 globalvar**, **74 → 75 playervar**. Validation covered restoring the original logic by reversing the changes, all 234 rules against the version with separate slots, exchange initialization, phase guards, color reevaluation, and a standard build using includes. Check: `node analysis/verify-remaining-elements.cjs`; [report and in-game test scenarios](analysis/remaining-elements-implementation-2026-11-02.md). In-game testing and load measurements have not yet been performed.

- Replaced 148 reads of `objectiveTypeList[0]` and `objectivePositionList[0]` with `currentObjectiveType` and `currentObjectivePosition`. The caches are updated immediately after each of the 11 locations that modify the arrays: resets, route generation and rollback, transitions to the next objective, and egg movement when taking damage. The HUD's type snapshot, `objectiveValue`, remains separate. Both caches share existing storage: `startMenuSpacingAngle → currentObjectiveType`, `startCamPos → currentObjectivePosition`; the Biomorphing color was moved to the `startPos` slot. Menu angle values 0/40 do not overlap with objective types 1–7. START GAME stops the cameras, removes menu visuals, and restores both caches; four guards after waits prevent late menu accesses to slots with new roles. The guards cost 21 elements compared with the version using separate variables; the result is **27,211 → 27,117 (−94 elements)**, with the global slot count still at 99. Validation covered cache updates, the phase boundary, all 231 compiled rules against the version with separate storage and the same guards, restoration of the original logic by reversing the substitutions, a build using actual includes, and temporary variable lifetimes. Recheck: `node analysis/verify-objective-head-caches.cjs`; [report](analysis/objective-head-caches-validation.json). In-game testing has not yet been performed.

- Shared `playervar` slots across menu and gameplay phases, objectives, and Team 1/Team 2 actor ownership: **107 → 74 fields (−33)**. Added `#!define` aliases and comments for each role. Four guards after waits prevent old voting and Biomorphing handlers from overwriting a slot's new contents. Build at this stage: **27,188 → 27,211 (+23 elements)**. All 231 compiled rules, field recipients, and the call graph were checked; in-game testing has not yet been performed. [Rationale and validation](analysis/player-slot-sharing-review-2026-11-02.md), [current field list](analysis/player-variables-review-2026-11-02.md).

- All references to `tmp0`, `tmp1`, and `tmp2` now use 82 descriptive `#!define` aliases at their points of use. They expand to the same global slots, including loops, macro inputs/outputs, and `evalOnce` captures. The aliases add no variables or elements; the compiled rules match. The placement of one Biomorphing guard was corrected: it now follows target cleanup, while the resource-granting helper macro remains unchanged.

- Biomorphing resource cleanup now shares `objectiveCount1` with mission generation and Satellite firing. Compilation produces no warnings; in-game testing has not yet been performed.

- Global variables are grouped by purpose and documented with comments. Boolean variables use the `is` prefix, arrays use the `List` suffix, and objective-specific state uses the `biomorphing` and `bosses` prefixes. Shared slots whose types change retain neutral names. - Replaced `reviveRadius`, `startTime`, `startCamDistance`, and `eliminationsNeededPerObjective` with `#!define` constants set to 5, 300, 6.5, and 50. - Valid vote checks for Challenge and Zombie Mode use slices of a shared `0–6` sequence appended to the compressed `numbersList`. - The pre-match HUD uses one line each for Challenge, Zombie Mode, Objective Type, and Enhancement, with text and color reevaluation. The new block contains no loops or `evalOnce`. - Temporary calculations without waits share `tmp0`, `tmp1`, and `tmp2`: 13 dedicated variables and the unused `losList` were removed, and a collision between the item HUD palette and index was fixed. - Another 10 temporary player variables were replaced with existing `tmp` slots: intermediate data for teleportation, damage, bioresource turn-ins, airstrikes, turrets, and launch pads, as well as synchronous counters. The unused `detectionRadius1` was removed; no new global slots were required. All `tmp` assignments include explanatory comments. - Added the `#!optimizeForSize` directive: the mode's element count decreased from **32,264 to 30,757**, saving **1,507 elements** (about **4.7%**). This technical change does not affect gameplay.
- Reduced repetition in difficulty tables; menu switching now uses cyclic indexing, identical effects are created in loops, and some empty separator rules were removed. The build after these changes in OverPy 9.7.20 uses **30,062 elements**. Earlier HUD changes in `src/global_start_menu.opy` were reverted: the pre-match HUD uses the original separate calls. Consolidating HUD creation into loops was deferred. Power-up optimizations in `power_ups.opy` were retained. At this stage, `#!optimizeForSizeAggressive` had not yet been enabled.
- Moved 26 long static numeric arrays (519 numbers) into a shared compressed `numbersList`; `null` was replaced with `0` in numeric tables. The generator `src/vas/create numbers.js` creates `NL_*_OFFSET` and `NL_*_LEN` constants, and the code uses `.slice(offset, len)` slices. Uniform arrays are built with loops: the initial `globalPlayerStats` contains 12 values of `-1`, Insanity speeds contain 21 ones, and uniform spawn probabilities contain 19 values of `5.263`. Their blocks were removed from `numbersList`. Loops do not reduce the size of short zero arrays or sparse tables, so those retain their previous implementations. The OverPy 9.7.20 build at this stage uses **29,210 elements**, **852 fewer** (about **2.8%**). The build completes without warnings; values, number order, and slice bounds were checked. In-game testing has not yet been performed.

- Reduced element-by-element assignments at startup: enhancement icons, the mixed objective pool, and the mutation list are assigned as arrays, while the list of 13 items is populated with a loop. Disabled mutations use `0`, followed by removal from the list, instead of `-1`. Removal of the turret's five effects was also consolidated into a loop; its HUD is removed separately.
- Selectively replaced long `if/elif` chains with `switch`: enhancement initialization, item use, and two objective management blocks. The change is applied only where it reduces the element count; cases without savings retain their previous implementation. The report `analysis/switch-optimization-results.json` records a separate stage: **29,177 → 29,162 elements** (−15).
- Replaced 17 subroutines with a single call site each with macros that expand inside the calling rule: mode setup, bot selection and parameters, mutations, objective and player entity management, biomaterials, satellite strikes, items, and Smolder's rage. Of these, 16 conversions were measured by `analysis/measure-single-use-subroutines.cjs`: **29,114 → 29,080 elements** (−34); `enablePowerupsMacro` was already present in its measurement baseline. Asynchronous calls through `startRule`, subroutines with early `return`, and subroutines that depend on the calling rule's conditions or control flow are not converted automatically.
- Added variant comparison scripts `analysis/measure-switch-candidates.cjs` and `analysis/measure-single-use-subroutines.cjs` with JSON reports. By default, they measure variants; `--apply` writes the transformations to source files. Running measurements also overwrites the corresponding report. The combined changes were verified with an OverPy 9.7.20 build: **29,080 elements**, **130 fewer** than the previous 29,210 (about **0.45%**). Intermediate reports use different baselines and do not account for all savings at this stage. There are no compiler warnings; the changes aim to reduce script size without changing gameplay mechanics, and in-game testing has not yet been performed.

- Implemented the full set of changes from the [further optimization analysis](analysis/Further-optimization-review-2026-10-31.md): seven enhancement fields, ten item fields, the exchange index, and two menu states were moved to separate player variables; repeated Smolder and gas cloud actions were consolidated into subroutines. Simplified barricade target filtering, repeated hero index lookups, and a redundant assignment. Three RGB colors and three vectors were stored in shared variables, and `#!optimizeForSizeAggressive` was enabled.
- The resulting build from source uses **27,803 elements**. Static checks covered 199 HUD/effect creation calls after the data representation change; 31 separate pre-match HUD lines and both barricade point slices were preserved. The compiler emits no warnings with the existing suppressions in `main.opy` retained. The [implementation report](analysis/further-optimization-implementation.json) includes measurements, renames, and hashes. The original comparisons can be reproduced with `node analysis/measure-further-optimizations.cjs --baseline-ref cf699010`; the script does not modify `src/`. In-game testing is still required, especially for menus, enhancements, items, Smolder, and gas clouds.
