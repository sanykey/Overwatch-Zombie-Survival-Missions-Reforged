# Overwatch Zombie Survival Missions Reforged

Переработка режима [Zombie Survival Missions](https://workshop.codes/786TW) для мастерской Overwatch на основе **ZSMM (786TW)**. Исходная версия сохранена в каталоге [ZSM examples/ZSMM (786TW)](<ZSM examples/ZSMM (786TW)>).

Цель проекта — максимально сократить количество элементов скрипта и убрать лишнее, чтобы освободить место для новых механик и улучшений героев. На первом этапе работа сосредоточена на технической оптимизации; по мере развития проекта здесь будут появляться конкретные изменения игрового процесса.

## Изменения

### Техническая оптимизация

- Добавлена директива `#!optimizeForSize`: количество элементов мода уменьшилось с **32 264 до 30 757** — на **1 507 элементов** (около **4,7%**). Это техническое изменение, которое не влияет на геймплей.
- Сокращены повторы в таблицах сложности; переключение меню переведено на циклическую индексацию, одинаковые эффекты создаются циклами, удалена часть пустых правил-разделителей. Сборка после этих изменений в OverPy 9.7.20: **30 062 элемента**. Предыдущие изменения HUD в `src/global_start_menu.opy` отменены: предматчевый HUD использует исходные отдельные вызовы. Дальнейшая оптимизация HUD отложена. Оптимизации предметов в `power_ups.opy` сохранены. `#!optimizeForSizeAggressive` не включена.
- 26 длинных статичных массивов чисел (519 чисел) вынесены в общий сжатый `numbersList`; в числовых таблицах `null` заменён на `0`. Генератор `src/vas/create numbers.js` создаёт константы `NL_*_OFFSET` и `NL_*_LEN`, в коде используются срезы `.slice(offset, len)`. Однородные массивы собираются циклами: начальный `globalPlayerStats` из 12 значений `-1`, скорости Insanity из 21 единицы и равномерные вероятности спавна из 19 значений `5.263`. Их блоки удалены из `numbersList`. Короткие массивы нулей и разреженные таблицы циклы не уменьшают, поэтому для них сохранены прежние варианты. Текущая сборка OverPy 9.7.20: **29 210 элементов**, на **852 меньше** (около **2,8%**). Сборка проходит без предупреждений; значения, порядок чисел и границы срезов проверены. Проверка в игре ещё не проводилась.

- Сокращены поэлементные присваивания при запуске: значки улучшений, пул смешанных заданий и список мутаций задаются массивами, а список из 13 предметов заполняется циклом. Для отключённых мутаций используется `0` с последующим удалением из списка вместо `-1`. Удаление пяти эффектов турели также объединено в цикл; её HUD удаляется отдельно.
- Длинные цепочки `if/elif` выборочно заменены на `switch`: инициализация улучшений, использование предметов и два блока управления заданиями. Переход применяется только там, где уменьшает число элементов; варианты без выигрыша сохранены в прежнем виде. Отчёт `analysis/switch-optimization-results.json` фиксирует отдельный этап: **29 177 → 29 162 элемента** (−15).
- 17 подпрограмм с единственным местом вызова заменены макросами, которые разворачиваются в вызывающем правиле: настройка режима, выбор и параметры ботов, мутации, управление сущностями заданий и игроков, биоматериалы, спутниковый удар, предметы и ярость Smolder. Из них 16 преобразований измерены скриптом `analysis/measure-single-use-subroutines.cjs`: **29 114 → 29 080 элементов** (−34); `enablePowerupsMacro` уже присутствовал в его исходной точке измерения. Асинхронные вызовы через `startRule`, подпрограммы с ранним `return` и зависимостью от условий или управления вызывающим правилом автоматически не преобразуются.
- Добавлены скрипты сравнения вариантов `analysis/measure-switch-candidates.cjs` и `analysis/measure-single-use-subroutines.cjs` с JSON-отчётами. По умолчанию они выполняют замеры, а `--apply` записывает преобразования в исходники; запуск замеров также перезаписывает соответствующий отчёт. Итог текущих изменений проверен сборкой OverPy 9.7.20: **29 080 элементов**, на **130 меньше** предыдущих 29 210 (около **0,45%**). Промежуточные отчёты используют разные исходные точки и не описывают всю экономию этого этапа. Предупреждений компилятора нет; изменения направлены на сокращение скрипта без изменения игровых механик, проверка в игре ещё не проводилась.

### Планы

- Дальнейшая оптимизация количества элементов и удаление лишнего.
- Добавление нового функционала.
- Улучшение героев.
