### Горизонтальные расстояния

Общий принцип для конечных координат:

```python
# Было: собираем точку B с высотой A, чтобы убрать вертикальную дистанцию.
distance(A, vect(B.x, A.y, B.z))
# Предлагается: убираем вертикальную компоненту разности.
magnitude((A - B) * vect(1, 0, 1))
```

Если A/B — игрок, в новом выражении нужен `.getPosition()`; готовый вектор используется напрямую. Точные подстановки находятся в скрипте кандидатов. Для Rescue сохранены порядок вычитания расстояний, деление на стартовую дистанцию, множитель 100 и ветка `rescueIsExtracting`. Алгебраическое преобразование `(a-b)/a` в `1-b/a` не предлагается: оно может изменить округление и поведение при нулевом знаменателе.

У botTarget сохраняются порог `2 * min(1, sizeScale)`, направление движения и live reevaluation внутри Start Throttle. В обработчике смерти остаются `eventWasEnvironment` и строгий порог `< 10`.

Проверены 10 000 числовых моделей, включая совпадающие XZ и точки на/рядом с порогом. Это проверка формулы в JavaScript, а не измерение числовой реализации Workshop. Перед внедрением в игровую версию нужны проверки движения ботов около порогов, смерти от окружения и прогресса Rescue, включая совпадение начальной и конечной точки по XZ.

Компромисс: добавляются векторное вычитание и умножение вместо сборки вектора из отдельных координат; чтений координат становится меньше. Выражения остаются в прежних местах, частота пересчёта прежняя. Меньшее количество элементов не доказывает ускорение native vector math; Server Load не измерялся.
