## Знак оси без вложенного conditional — −12

В `abilities/augment_dash.opy`:

```python
# Было
augmentDashDirection = vect(1 if augmentDashDirection.x > 0 else -1 if augmentDashDirection.x < 0 else 0, 0, 1 if augmentDashDirection.z > 0 else -1 if augmentDashDirection.z < 0 else 0)
# Предлагается
augmentDashDirection = vect((augmentDashDirection.x > 0) - (augmentDashDirection.x < 0), 0, (augmentDashDirection.z > 0) - (augmentDashDirection.z < 0))
```

В числовой арифметике Workshop True соответствует 1, False — 0. Для каждой оси:

| Вход | x > 0 | x < 0 | Разность | Прежнее значение |
|---|---:|---:|---:|---:|
| Положительный | 1 | 0 | 1 | 1 |
| Ноль | 0 | 0 | 0 | 0 |
| Отрицательный | 0 | 1 | −1 | −1 |

Приведение boolean к числу уже применяется в текущем проекте, например в `30 * eventPlayer.powerUpJetpackIsFlying` в applyScaledMoveSpeed; агрессивная сборка также использует True вместо числовой единицы в арифметических аргументах. Новый экспорт содержит именно `Subtract(Compare(X Component Of(...), >, Null), Compare(X Component Of(...), <, Null))` и аналогично Z.

Сохраняется прежнее приведение любых ненулевых осей к ±1, а не нормализация по длине: диагональный Dash остаётся под 45 градусами при любом соотношении ненулевых X/Z. Нет деления, Normalize, epsilon, округления или порога подавления малого аналогового ввода. Оба знака определяются теми же строгими сравнениями с нулём. Сначала целиком вычисляется RHS вектора, затем он записывается в прежний tmp0.

Это другой вариант, чем ранее отсеянная нормализация одномерного вектора: здесь нет зависимости от поведения Normalize на нуле или малом векторе.

**80 012 моделей осей** проверили обе формулы для обычных float64/float32 значений и отдельных граничных значений (включая отрицательный/положительный ноль, ±1, ±0.00001, ±1e−30 и минимальные ненулевые значения модели). Проверены также **20 000 моделей полного направления**. Модели проверяют подстановку сравнений/арифметики; это не игровой прогон нативных входов.

Компромисс: новая формула содержит два сравнения и вычитание; исходная — вложенный conditional. Возможное короткое вычисление ветвей и стоимость нативного вычитания в движке не профилировались. Меньшее число элементов не доказывает ускорение.

## Сравнение с False только для известного вектора — −2

```python
# Было
if augmentDashDirection != vect(0, 0, 0):
# Предлагается
if augmentDashDirection != false:
```

Здесь важен тип и область значений. Перед проверкой tmp0 **всегда** перезаписывается конструктором `vect(signX, 0, signZ)`, где signX/signZ принадлежат {−1, 0, 1}. Между построением вектора и проверкой нет waits; существующая applyDamageReceivedModifier не переписывается. Возможны ровно девять векторов.

По контракту Workshop comparisons, приведённому в [AGENTS.md](../AGENTS.md), нулевой вектор равен False. Для девяти возможных векторов только vect(0,0,0) удовлетворяет этому сравнению. Поэтому именно в этом месте обе проверки дают один результат; в исходник добавлен комментарий об этой области значений.

Это **не** замена произвольного `X != 0` truthiness-проверкой. Числовой 0/Null не используется как замена нулевого вектора. Пустые массивы, игроки и скаляры не могут попасть в данную проверку после обязательного конструктора vect. Применять такой приём к произвольным shared-слотам без доказанного типа нельзя.

Скомпилированный guard проверен отдельно:

```text
# Было: компилятор представляет нулевой вектор как Left + Right.
Skip If(Compare(Global.tmp0, ==, Add(Left, Right)), True);
# Стало: остаётся явное сравнение с False, без shorthand If(Global.tmp0).
Skip If(Compare(Global.tmp0, ==, False), True);
```

В обоих случаях пропускается ровно один прежний Apply Impulse. Проверены все девять значений направления по указанному контракту сравнения; сам Workshop не эмулировался.
