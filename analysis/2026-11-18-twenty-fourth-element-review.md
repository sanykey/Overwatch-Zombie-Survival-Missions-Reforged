## Общая инициализация результата голосования

В `src/game/global_start_menu.opy` есть ровно два синхронных вызова `selectVoteWinner()`:

- determineZombieMode сначала записывает zombieSetting = 0, считает голоса и передаёт эту настройку в voteWinnerResult;
- determineObjectiveType сначала записывает objectiveTypeSetting = ObjectiveType.NO_PREFERENCE (0), считает голоса и передаёт её в тот же voteWinnerResult.

Между начальными сбросами и передачей результата нет ожиданий и промежуточных записей в соответствующие настройки. Циклы меняют только массивы счётчиков голосов и scratch-индекс. Помощник всегда получает нулевого начального победителя.

Предлагается удалить две записи voteWinnerResult в вызывающих функциях и поставить `voteWinnerResult = 0` первым действием уже существующего selectVoteWinner. Локальный комментарий контракта input/output уточняется: tmp1 — входной список счётчиков, tmp2 — результат, который помощник сам начинает с нуля. Первоначальные сбросы глобальных настроек остаются на прежних местах.

Тело выбора победителя сохраняется: обход вариантов, сравнения количества голосов, последовательные случайные решения при равенстве, публикация результата и резервные варианты All Zombies/Mixed Objectives. Нулевой начальный результат остаётся тем же native Null, который OverPy использует для числового 0. Ни одна проверка значения не заменяется проверкой истинности.
