## Общее время спасения

В `src/game/players_game_in_progress.opy`, правиле `REVIVE PLAYER OR ADVANCE DEATH TIMER`:

```python
# Было
mustReviveTime -= 0 if mustReviveTime <= 30 else 10
# Предлагается
mustReviveTime = max(30, mustReviveTime - 10)
```

Проверены все записи в mustReviveTime: инициализация в global_startup.opy значением 60 и это уменьшение после окончательной смерти игрока. Во время игры достижимы только 60, 50, 40 и 30. Последовательность остаётся 60→50→40→30→30. Персональный rescueTimeRemaining, его изменения при реанимации/выходе купола и reconnect-данные не заменяются этой формулой: у них другой диапазон.

Эквивалентность опирается на это закрытое множество значений общего таймера. Для произвольного стороннего значения ниже 30 или промежуточного 35 формулы не эквивалентны. В текущем коде таких записей нет; скрипт явно проверяет список всех записей в переменную.

В экспорте единственный Modify Subtract с If-Then-Else заменяется одним Set Global Variable с Max/Subtract. Остальное полное правило совпадает с базой: сообщения, сохранение состояния, телепортация, ожидания и возрождение не меняются.
