## Ammo Pack — суммарно −19

В [augments.opy](../src/abilities/augments.opy) `AMMO PACK REFILL FALLBACK`
завершается полной пересборкой состояния из пяти полей:

```python
state = [below0, below1, isReloading, state[3], state[4]]
```

Последние два поля — сохранённый боезапас в начале перезарядки; они не меняются
в этой точке. Предложение — три присваивания:

```python
eventPlayer.augmentAmmoFallbackState[0] = eventPlayer.getAmmo(0) < eventPlayer.getMaxAmmo(0)
eventPlayer.augmentAmmoFallbackState[1] = eventPlayer.getAmmo(1) < eventPlayer.getMaxAmmo(1)
eventPlayer.augmentAmmoFallbackState[2] = eventPlayer.isReloading()
```

Проверен контракт массива: `AMMO PACK MAGAZINES` сначала сбрасывает состояние в Null,
затем создаёт ровно пять полей либо оставляет Null. Fallback допускается только
для нужного Augment, совпавшего hero/weapon и ненулевого состояния. Другие писатели
состояния обновляют только снимки 3/4. Во время валидного вызова это массив длиной 5;
пересоздавать его ради сохранения последних двух полей не требуется.
Для произвольного повреждённого состояния иной длины эквивалентность не заявляется.

Между тремя записями нет wait или вызова другого обработчика; правила выдачи патронов,
пороги native/full, исключение отменённой перезарядки и Widowmaker остаются прежними.
Сохранение всех пяти полей проверено на 2304 сочетаниях прежних/новых флагов и снимков.

Компромисс: вместо одного Set Player Variable появляются три Set Player Variable
At Index; зато исчезают построение массива и два чтения сохранённых полей.
Число Workshop elements меньше, но ускорение CPU без измерений не установлено.

### Общий признак завершения перезарядки

Внутри того же clip-loop дважды вычисляется:

```python
eventPlayer.augmentAmmoFallbackState[2] and not eventPlayer.isReloading()
```

Сохранить его в существующий свободный tmp2 под alias `augmentAmmoReloadFinished`
**внутри каждой итерации**, сразу после чтения native capacity, затем использовать
в обоих местах длинного предиката выдачи патронов. tmp0 остаётся индексом clip,
tmp1 — native capacity. Между записью и двумя чтениями нет ожиданий, вложенных
вызовов, damage или reevaluated visual captures. Список глобальных переменных не меняется.

Не выносить вычисление перед циклом: Set Ammo для первого clip может изменить
нативное состояние reload, и второй clip должен читать актуальное значение.
Проба сохраняет пересчёт на каждой итерации. Модель сравнила 35 840 сочетаний
capacities/ammo/snapshots, обычного героя/Widowmaker, прежних флагов и последовательностей
reload для двух clips, включая смену reload между ними.

Компромисс: добавляется scratch-присваивание на clip вместо повторного вычисления
предиката. Новых фоновых проверок нет; fallback продолжает реагировать на прежние
границы ammo/full и reload, а не проверять каждый выстрел.

## Extraction — суммарно −5

В [objective_type_extraction_point.opy](../src/objective_types/objective_type_extraction_point.opy)
две горизонтальные дистанции можно выразить длиной XZ-проекции разности позиций:

```python
# PLAYERS IN EXTRACTION POINT CONTROL:
magnitude((eventPlayer.getPosition() - currentObjectivePosition) * vect(1, 0, 1)) < objectiveRad

# В прежнем фильтре resurrect внутри WIN/LOSS CONDITIONS:
magnitude((currentObjectivePosition - player.getPosition()) * vect(1, 0, 1)) < objectiveRad
```

Обе исходные формы искусственно подставляли равные Y в один конец Distance Between.
Новые выражения зануляют Y после вычитания. Проверка высоты через eye position,
hasSpawned, допуски extraction и ветвление победы/поражения сохраняются.
Радиус, состав получателей resurrect, flight animation и waits не меняются.
Модель длины проекции прошла 10 000 конечных наборов координат, включая границу
10 и соседние значения. Это JavaScript-модель, не тест точности Workshop.
