## Почему пустой case занимает элементы

В текущей сборке OverPy switch компилируется в структурный `If(True)` и Skip с двумя массивами: ID ветвей и числовыми смещениями. Каждая пустая ветвь всё равно имеет ID, смещение и маркер границы ветви. Её удаление сокращает скомпилированный dispatch, хотя полезных действий в ней не было. Выигрыш измерен в реальных экспортах, а не по числу исходных строк.

Для исключённого ID теперь срабатывает прежний default-переход к концу switch. В этих switch нет default с игровыми действиями. Поэтому выбор удалённого ID по-прежнему выполняет ноль действий внутри switch, а последующий код продолжается как раньше.

## Два пустых Boss case — −10

В `src/core/subroutines.opy`, `objectivesManagement()`, встречается два блока:

```python
case ObjectiveType.BOSSES:
    break
```

Первый — в switch эффектов завершения задания. Второй — в switch инициализации следующего задания. Оба блока не содержат эффектов, переменных, вызовов или ожиданий.

Удаляется только каждый case/break, а не логика самого Boss-режима. Остаются прежними сброс общей фазы, переход к следующей точке, сообщения о завершении/начале, создание HUD/иконок/текста, инициализация и поведение босса в других правилах. Нет переноса действий, добавления ранних return или падения в следующую ветвь: неизвестный для таблицы ID попадает в конец switch.

case Enhancement.BRAIN_KILLER:

Ветка с ID 3 теперь использует тот же выход из switch, что и другие ID без инициализируемого состояния. Все остальные enhancement-ветви остаются прежними.

## Проверка скомпилированных переходов

Скрипт разбирает фактический список Workshop Actions с учётом строковых литералов и вложенных аргументов. Из каждого изменённого switch извлекаются настоящие массивы ID и Skip-offsets.

Для двух ObjectiveType-switch и одного enhancement-switch проверены **72 пути dispatch**: ID −2..20 и 100 для каждого блока. Это включает все допустимые ObjectiveType/Enhancement ID, NO_PREFERENCE, отрицательные/неизвестные значения и удалённые 2/3.

Для каждого пути вычисляется реальная позиция перехода по `1 + Index Of Array Value(...)` и таблице смещений. Далее сравнивается последовательность скомпилированных действий ветви до её Else/End. Аудит намеренно принимает только плоские ветви и завершится ошибкой при неподдерживаемой вложенной структуре; текущие три блока плоские.

Подтверждено:

- в исходной таблице удалённый ID присутствует, в новой отсутствует;
- default-offset в обоих вариантах указывает на End соответствующего switch;
- удалённые ID дают пустую последовательность действий и до, и после;
- остальные ID дают те же действия в том же порядке;
- после замены проверенных switch их семантическими представлениями весь окружающий исполняемый текст правил совпадает;
- совместная проба меняет только `objectivesManagement` и `PLAYER ENHANCEMENT AND AUGMENT INITIALIZATION`.

Это структурная проверка диспетчеризации Workshop, а не запуск игрового планировщика. Она не эмулирует эффекты, сообщения или содержимое вызываемых подпрограмм; сами такие команды сравниваются побуквенно, а правила вызываемых подпрограмм остаются неизменными.
