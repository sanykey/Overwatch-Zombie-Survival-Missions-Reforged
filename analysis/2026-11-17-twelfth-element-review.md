### Неиспользуемая successfulTeleportStatus — −5

В `game/bots_game_in_progress.opy` есть объявление и тело подпрограммы, но нет вызовов. Во всех исходниках её имя встречается только три раза: declaration, def и @Name. Это проверяется скриптом перед преобразованием.

Тело только устанавливает `botIsTeleportConfirmed = true`, если флаг ещё не установлен. Само наличие Subroutine-правила его не запускает. Удаление declaration и def устраняет ровно одно скомпилированное правило; остальные правила при отдельной пробе не меняются. Логика действующих телепортов и изменение этого флага в используемых правилах остаются прежними.

### Предыдущий боезапас магазина — −5

В `abilities/augments.opy`, внутри `AMMO PACK REFILL FALLBACK`, выражение

```python
eventPlayer.augmentAmmoFallbackState[augmentAmmoFallbackClipIndex + 3]
```

дважды используется в одном предикате Widowmaker. Предлагается после существующего чтения `augmentAmmoReloadFinished`, внутри цикла по магазинам, добавить:

```python
# Prior-clip reload snapshot: synchronous predicate only, no waits or calls.
#!define augmentAmmoPreviousClipAmmo tmp3
augmentAmmoPreviousClipAmmo = eventPlayer.augmentAmmoFallbackState[augmentAmmoFallbackClipIndex + 3]
```

Оба прежних обращения в предикате заменяются alias-именем. Этот снимок хранит значение из существующих полей 3/4, сохранённых при начале reload; он не снимает новый `getAmmo()` и не меняет записываемый боезапас. Новый alias не является объявлением Workshop-переменной: используется имеющийся глобальный tmp3.

Контракт tmp3: присвоить отдельно для каждого магазина, прочитать только при немедленной проверке условия, не сохранять через wait/call/chase/HUD. В рассматриваемом участке tmp0 — индекс магазина, tmp1 — native capacity, tmp2 — reload-finished; слоты не пересекаются. Между новым присваиванием и предикатом нет записей в fallbackState и вызовов других подпрограмм. После проверки снимок больше не нужен.

Сохранено повторное чтение `isReloading()` **в каждой итерации**: Set Ammo первого магазина может изменить native reload state для второго. Четыре исходных чтения текущего `getAmmo(clipIndex)` остаются на своих местах. Финальное обновление fallbackState[0..2] и прежние snapshots[3..4] также сохранены.

Проверены 11 200 моделей предиката/результата refill для обоих магазинов, разных native/target capacity, боезапаса и прошлых значений, флагов reload/full и Widowmaker. Это числовая модель подстановки, а не воспроизведение нативной перезарядки.

Компромисс: добавляется одно отдельное присваивание scratch на каждую итерацию, устраняются два текстовых повторения индексированного выражения в предикате. Нельзя по этому замеру утверждать снижение CPU; выражение снимка теперь находится перед If. Обработчик по-прежнему запускается по границам состояния, а не становится новым опросом в цикле. Нужны игровые проверки полного/отменённого reload, двух магазинов, героев с native Set Max Ammo, fallback и выстрела Widowmaker в момент завершения перезарядки.
