# Упрощение PLAYER INTERACT

Удалены резервирование ввода по типу аугмента, выход после взаимодействия WRESTLER с зомби, задержка после запроса броска и состояние баррикады `-2`, которое обслуживало это резервирование. Захват/бросок и операция с предметом теперь могут выполняться одним нажатием. Проверки в собственных правилах телепортации и установки баррикады сохранены.

Использование powerup требует удерживать Interact 0,25 с без Crouch. `waitUntil` завершает ожидание при первом обнаруженном приседании или потере условий правила. После прерывания правило заканчивается без использования предмета; отпускание Crouch при всё ещё удерживаемом Interact не запускает правило повторно. Приседание после уже выполненного использования не отменяет его задним числом. Как и остальные проверки кнопок Workshop, это работает с состояниями, наблюдаемыми движком.

Открытие контейнера, подбор/обмен powerup, проверка вместимости рюкзака SCAVENGER и переключение запасов сохранены. Только у SCAVENGER приседание направляет подобранный предмет в рюкзак; у остальных аугментов оно не препятствует подбору.

## Проверка

- Сравнение скомпилированных правил без комментариев: изменился только `PLAYER INTERACT`; порядок и количество правил сохранены.
- Проверено наличие прерываемого ожидания, отдельного `Abort If Condition Is False` и проверки Gameplay/Crouch перед использованием в Workshop-коде. Новых переменных нет; временные глобальные значения по-прежнему не сохраняются через ожидание.
- `git diff --check` проходит. `main.ws.txt` пересобран; файл исключён из Git настройками проекта.
- Для повторной проверки: `node analysis/2026-11-15-simplify-interact.cjs after`. Режим `before` предназначен только для захвата исходного состояния перед изменениями.

Сокращение числа элементов не является измерением скорости. Вместо фиксированного ожидания теперь отслеживаются Crouch и условия правила в течение окна 0,25 с, только при попытке использования предмета. Удалены проверки типов аугментов и дополнительные ожидания WRESTLER; циклов опроса и новых постоянно активных правил нет. Внутриигровые проверки не выполнялись.

Восстановлен первоначальный вариант: `isGameplayActive` проверяется в Actions, а после ожидания используется отдельный ранний выход `if not ruleCondition: return`. Сохранён обход проблемы исчезновения новых героев при переходе от голосования к выбору героя.

Рекомендуемые игровые сценарии: обычное использование за 0,25 с; отпускание Interact раньше срока; Crouch до Interact; короткий Crouch во время ожидания с последующим долгим удержанием Interact; подбор SCAVENGER в свободный/полный рюкзак; одновременный захват/бросок зомби и подбор; подбор при попытке телепортации или установки баррикады.
