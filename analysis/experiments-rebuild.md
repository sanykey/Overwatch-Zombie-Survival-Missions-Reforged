## Регрессия на шаге 10: исследование отложено

Пользователь уточнил: предыдущие сборки проверены без воспроизведения; на
`10-apothecary-full-health-packs.ws.txt` баг воспроизведён трижды. Все воспроизведения
в этом расследовании происходят во время голосования, до старта игрового процесса.
По просьбе пользователя шаг 10 отменён отдельным revert-коммитом (шаг 12),
исследование отложено. Кэш иконок из шага 11 сохранён в основной ветке;
в диагностические сборки ниже он не включался.

Новое правило шага 10 требует `isGameplayActive == true`; штатно Set Health
во время голосования не выполняется. Поэтому само изменение здоровья не объясняет
наблюдение. Проверяем влияние текста и присутствия правила в загруженном скрипте;
внутренняя причина, в том числе возможная проблема памяти, пока не установлена.

- `experiments/rebuild/10a-text-only.ws.txt`: шаг 09 + только два удлинённых описания,
  без нового правила; 28 595 элементов, 301 правило.
- `experiments/rebuild/10b-rule-only.ws.txt`: шаг 09 + только новое правило, оба
  описания в точности из шага 09; 28 613 элементов, 302 правила.

Обе сборки скомпилированы без предупреждений; точный состав правил и неизменность
объявлений переменных проверены относительно 09/10. Источники и основной экспорт
остаются на шаге 11. На 10b пользователь воспроизвёл баг при голосовании;
результат 10a пока не сообщён. Удлинённые описания не обязательны для воспроизведения.
Сводка: `experiments/rebuild/10-split-validation.json`.

Пользователь предложил проверить ongoing-условие Health(Event Player) ==
Max Health(Event Player) во время смены героя. Отсутствие запуска действий не
исключает внутреннюю обработку условий. При этом разработчик Workshop в ответе

https://us.forums.blizzard.com/en/overwatch/t/why-did-my-server-shut-down/456771/8
Первым условием уже стоит isGameplayActive == true; чтение здоровья в pregame
не доказано. Проверяем присутствие/обработку этого сравнения в Conditions отдельно.

- `experiments/rebuild/10c-no-health-condition.ws.txt`: на базе воспроизводящей 10b
  удалено только сравнение Health/Max Health из ongoing-условий. Set Health в теле
  сохранён. 28 610 элементов.
- `experiments/rebuild/10d-health-check-in-body.ws.txt`: то же сравнение перенесено
  в If внутри тела правила, после остальных условий. Оба вызова Health/Max Health
  остаются в скрипте, в ongoing-условиях их нет. 28 616 элементов.

Обе версии диагностические, только для проверки голосования. Без условия здоровья
меняется повторный запуск правила во время игры; это не готовое исправление Apothecary.
В каждой версии изменилось ровно одно правило относительно 10b; остальные 301 правило
и объявления переменных идентичны. Предупреждений нет. Пользователь воспроизвёл баг
на обеих версиях, поэтому наличие Health/Max Health в ongoing-условиях не требуется.
Сводка: `experiments/rebuild/10-health-condition-validation.json`.

Пользователь отдельно проверил 10d: после удаления обоих условий
`Global.isGameplayActive == True` и `(Event Player).augmentId == 8` воспроизведения
не было. Позже пользователь уточнил: наличие любого из этих условий по отдельности
также воспроизводит баг. Эксперимент с явной инициализацией не помог.

- `experiments/rebuild/10e-explicit-defaults.ws.txt`: исходная 10d с обоими
  подозрительными условиями. В Initialize global variables первым действием явно
  записывается isGameplayActive = False. Новое событие Player Joined Match для Team 1
  без ожиданий/условий спавна присваивает augmentId числовой 0. Существующий сброс
  augmentId в PLAYER MENU INITIALIZATION тоже оставлен числовым 0 вместо Null.

В исходной версии augmentId уже присваивалось нулевое значение в меню, но после
ожидания; раннего присваивания при входе не было. OverPy оптимизирует числовой 0
в Null, поэтому в диагностическом экспорте две записи сохранены именно как `0`.
Глобальное значение False сохранено буквально и перенесено в начало инициализации.
Изменились два правила и добавлено одно событие входа; остальные 300 правил,
включая Apothecary и механизм возврата к выбору героя, совпадают с 10d.
Объявления переменных неизменны. 28 621 элемент (+5 к 10d): +3 после компиляции
инициализации и события входа, ещё +2 за сохранение двух числовых нулей вместо Null.
Стоимость литералов проверена отдельной компиляцией без оптимизации размера.
Источники и основной экспорт не менялись. Версия диагностическая для голосования,
с прежним ограничением 10d на повторный запуск правила во время игры.
Сводка: `experiments/rebuild/10-explicit-defaults-validation.json`. Пользователь
воспроизвёл баг; дальнейшие эксперименты отложены по его просьбе.

Длина описания меню выросла с 149 до 171 символа, HUD — с 64 до 82. Количество
Custom String в соответствующих правилах осталось 14 и 20. Это не устанавливает
безопасность строк для движка; проверка 10a отделяет их влияние от нового правила.

## Порядок работы

- Один небольшой исполняемый шаг — один коммит с обновлённым `main.ws.txt`.
- После каждого такого коммита ждать результата проверки в игре; без него
  не переносить следующую часть. Сборка без предупреждений не заменяет игровой тест.
- Для каждого шага измерять элементы Workshop и проверять фактический diff.
- Исправления меню, цвета, описания и оптимизации переносить отдельно от механик.
- Делить по минимальным завершённым изменениям: захват зомби без гарантированного
  освобождения или выбор ещё не реализованного улучшения не являются безопасными шагами.
- Не копировать устаревшие промежуточные реализации, если в исходной ветке они
  заменены. Leech переносить как Augment, Dead Weight — как Enhancement.
- Артефакты игровых проверок хранить в игнорируемой папке `experiments/rebuild/`.
  Старые диагностические скрипты и артефакты не включать в коммиты переноса.
