### Позиция щупальца Slimer — −4

Четыре использования: создание beam при инициализации бота, начальная позиция щупальца, live destination обратного chase и условие ожидания возврата.

```python
# Было
eventPlayer.getEyePosition() + offsetUpHalfConst * eventPlayer.sizeScale if eventPlayer.isInAir() else eventPlayer.getEyePosition()
# Предлагается
eventPlayer.getEyePosition() + offsetUpHalfConst * (eventPlayer.sizeScale if eventPlayer.isInAir() else 0)
```

Воздух: прежнее смещение на половину sizeScale вверх. Земля: eye position плюс нулевой вектор. `offsetUpHalfConst` — неизменяемый вектор `0.5 * Vector.UP`; sizeScale в этих местах — конечный числовой масштаб бота. Ни scratch, ни evalOnce не добавляются: chase/beam остаются переоцениваемыми, переход воздух/земля и масштаб не фиксируются заранее.

Компромисс: на земле новая формула выполняет умножение на 0 и сложение с нулевым вектором вместо выбора eye position напрямую. Чтений eye position в экспорте меньше, но снижение затрат CPU не установлено. В игре проверить Slimer на земле/в воздухе, изменение масштаба, вытягивание и возврат щупальца, попадание/промах, смерть и crowd control во время атаки.

### Газ Behemoth — −3

```python
# Было
distance(behemothGasCloudPosition, vect(x.getEyePosition().x, behemothGasCloudPosition.y, x.getEyePosition().z))
# Предлагается
magnitude((behemothGasCloudPosition - x.getEyePosition()) * vect(1, 0, 1))
```

Сохраняются eye position цели, строгий порог `< behemothGasCloudRadius`, отдельная проверка вертикального расстояния, исключения уже поражённых/защищённых игроков и порядок накопления целей. В существующие scratch-контракты газового цикла изменений нет. Проекция заменяет сборку вектора из отдельных координат; реальная скорость native vector math не измерялась. Проверить попадания у края облака и на разных высотах, в том числе при нескольких облаках.

### Kill Zone — −2

В одинаковых выражениях радиуса кольца и Light Shaft:

```python
# Было
sqrt(objectiveRad ** 2 - ((abs(localPlayer.getPosition().y - killZoneCenter.y)) ** 2))
# Предлагается
sqrt(objectiveRad ** 2 - ((localPlayer.getPosition().y - killZoneCenter.y) ** 2))
```

Квадрат конечного числа не зависит от знака. Внешний sqrt и его аргумент не переставляются, существующее поведение при отрицательном подкоренном выражении не исправляется. Число визуальных сущностей, позиция и видимость не меняются. Удаляется по одному вызову abs при reevaluation каждого из двух визуалов; выигрыш Server Load не измерялся. Проверить отображение Kill Zone сверху, снизу и на границе высоты.
