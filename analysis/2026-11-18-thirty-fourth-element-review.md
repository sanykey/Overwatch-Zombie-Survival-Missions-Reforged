## Общая палитра вместо повторяющихся Color

В проекте уже есть неизменяемый augmentColorListConst, используемый тремя цветовыми полями меню Augment. Четыре другие палитры повторяют большую часть этих цветов: предметы, меню зомби, меню заданий и меню Enhancement. Ещё один массив из шести цветов задаёт цвет заголовка Challenge.

Предлагается сохранить первые 11 цветов augmentColorListConst в прежнем порядке и добавить хвост:

| Индекс | Значение |
| ---: | --- |
| 11 | Color.PURPLE |
| 12 | Color.GRAY |
| 13 | Color.ROSE |
| 14 | null |

Индексы Augment остаются 0..10. Проверены все три записи augmentId: сброс к NO_PREFERENCE, выбор по модулю LEECH + 1 и случайный выбор KEVLAR..LEECH. В исходниках нет обхода палитры по её длине, а все три чтения AUGMENT_COLORS индексируются augmentId. Поэтому все допустимые Augment ID сохраняют прежние цвета. Доступ к добавленному хвосту предназначен только для реконструкции других палитр. При будущем добавлении Augment нужно согласованно пересмотреть эту общую палитру и её числовые индексы.

Остальные палитры строятся по индексам из существующего numbersList:

```python
numbersList.slice(NL_POWERUP_COLORS_OFFSET, NL_POWERUP_COLORS_LEN).map(lambda index: augmentColorListConst[index])
```

Аналогично строятся три прежние меню-палитры и только цвет заголовка Challenge. У Challenge индекс выбранного голоса применяется **после** Map, как и прежде к готовому массиву цветов; преобразование не вводит дополнительный нулевой индекс общей палитры при выходе за границы массива голосов. Два остальных цветовых поля Challenge сохраняют свои исходные массивы.

PowerUp-палитра объявляется/инициализируется после общей палитры. В скомпилированном Initialize global variables проверен порядок: numbersList, затем augmentColorListConst, затем powerUpColorListConst. Числовые индексы некоторых объявлений global variables меняются из-за переноса объявления, но имена, набор и число переменных сохраняются; все ссылки в скомпилированных правилах остаются именованными и проверены сравнением.
